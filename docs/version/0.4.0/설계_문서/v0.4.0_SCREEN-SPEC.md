# SCREEN-SPEC — 냉장고 관리 웹 앱 화면 명세

> 근거: PRD · ARCHITECTURE · DECISIONS · USER-WORKFLOW
> 이 문서는 위 문서들에 **이미 정해진 내용**만 화면 기준으로 묶었다. 정해지지 않은 항목은 이 문서에서 정하지 않고 13절에 모았다.
> API 주소와 필드 정의는 이 문서에 쓰지 않는다. 화면이 하는 일과 보이는 것만 적는다.

**표시 약속**: (US-번호, OQ-번호)는 PRD 항목, (D-번호)는 DECISIONS 항목이다. (ARCH n절)은 ARCHITECTURE, (시나리오 N)은 USER-WORKFLOW 의 근거 위치다.

## 0. 공통 규칙 (모든 화면에 적용)

- 로그인해야 쓸 수 있다. 로그인하지 않았으면 어느 화면을 열어도 로그인 화면이 보인다. (US-012, D-059)
- 내 식품만 보인다. 다른 사람의 식품은 어디에도 보이지 않는다. (US-012, D-061)
- 로그인은 마지막으로 앱을 쓴 뒤 30분 동안 유지된다. 한 계정으로 휴대폰과 컴퓨터에서 동시에 쓸 수 있고, 한쪽을 로그아웃해도 다른 쪽은 유지된다. (D-052, D-053, D-054)
- 브라우저에서 쓴다. 휴대폰 화면을 우선으로 하고, 컴퓨터에서도 보인다. (PRD 2절)
- 인터넷이 없으면 쓸 수 없다. (D-040)
- 성공 안내 메시지는 없다. 화면이 바뀐 것(막대가 생기거나 사라짐, 로그인 화면으로 돌아감)으로 성공을 안다. (시나리오 6 ~ 19)
- 저장 · 등록 · 수정 · 삭제 · 다 먹음 · 버림 · 되돌리기 · 가입 · 로그인 · **사진 올리기 · 한꺼번에 등록 · 추천받기 · 탈퇴** 버튼은 처리가 끝날 때까지 다시 누를 수 없다. 연타해도 요청은 한 번만 간다. 끝나거나 실패하면 다시 누를 수 있게 돌아온다. (OQ-48, D-099, D-112)
- 화면의 입력 검사는 미리 알려 주는 용도이고, 최종 판단은 API 가 한다. (D-010, ARCH 2절)
- 여유 · 주의 · 임박 · 지남 판정과 기록 숫자 세기는 API 만 한다. 화면은 받은 값을 보여 주고 색을 입히기만 한다. (D-009, ARCH 2절)
- 화면이 하는 날짜 계산은 막대를 이번 주 7일에 맞춰 자르는 것뿐이다. (D-016)
- "오늘"은 서버 시계의 한국 시간이다. 화면은 API 가 준 오늘 날짜를 쓴다. (D-021, D-087, D-088)
- 날짜는 "26년 10월 30일(금)" 모양으로 보인다. (D-031)
- **로그아웃 버튼은 로그인 화면을 뺀 모든 화면의 맨 위 오른쪽에 있다.** (D-130, 13.1 의 13번)
- 확인 창은 **삭제할 때**, **다 먹음 · 버림으로 처리할 때**, **입력하다가 탭을 눌러 이동할 때**, **탈퇴할 때** 네 경우에 뜬다. (OQ-06, D-083, D-128, 시나리오 13, 14, 19, 20)
- 실패하면 쉬운 오류 메시지가 화면 위에 보인다. 사용자가 입력한 내용은 그대로 남고, 아무것도 바뀌지 않는다. (OQ-04, 시나리오 21)
- AI 가 하는 일(사진 읽기, 음식 추천)은 처리 중 표시가 보이고, 끝나기 전에는 같은 버튼을 다시 누를 수 없다. 사진은 저장하지 않는다. (D-102, D-112)
- 안내 · 오류 문구는 구현 단계에서 쉬운 말로 정한다. 로그인 실패 · 중복 이메일 · 비밀번호 규칙 · 찾을 수 없는 식품 문구는 이미 정해져 있고, AI 안내 한 줄과 AI 응답 실패 · 사진 읽기 결과 만료 문구도 정해져 있다. (OQ-03, ARCH 3절, D-105)

|---|---|---|
| 오류 알림 | 실패하면 쉬운 오류 메시지를 화면 위에 보이고, 입력한 내용은 지우지 않는다 | OQ-04 |
| 빈 화면 안내 | 안내 문구 + 식품 등록 버튼. 홈이 비었을 때, 기록이 완전히 비었을 때, 음식 추천할 식품이 없을 때 | OQ-05, D-071 |

| 상태 색 | 여유 초록 / 주의 노랑 / 임박 빨강 / 지남 검정. 색만 입힌다. 홈과 기록이 같은 색을 쓴다 | US-008, D-009 |

| 로그아웃 버튼 | 로그인 화면을 뺀 모든 화면의 맨 위 오른쪽. 누르면 이 기기의 로그인만 끝내고 로그인 화면으로 간다 | D-130, D-054, D-060 |

| 로그인 필요 처리 | 로그인하지 않았거나 30분이 지나면 로그인 화면으로 보낸다 | D-055, D-059 |

| AI 안내 한 줄 | '사진으로 등록' 버튼 아래에 작고 연한 글씨로 "AI 가 사진에서 식품 목록을 줘요". 식품마다 표시를 붙이지 않는다 | US-018, D-105 |
| 사진 올리기 | 사진 한 장 선택. jpg · png · webp, 5MB 이하를 미리 검사하고 안 맞으면 올리지 않고 안내 | US-017, D-101, ARCH 2절 |
| 나열된 식품 줄 | 확인 화면의 한 줄. 이름 · 수량 · 단위 · 구매일 · 보관 방법(금지된 방법은 흐리게) · 기한 · 빼기 | US-019, D-104, D-108 |
| 음식 카드 | 음식추천 결과 한 개. 음식 이름과 재료(가진 것 / 없는 것) | US-021, D-121 |
| 탈퇴 확인 창 | "삭제는 되돌릴 수 없다"는 안내 + 비밀번호 입력칸 + 확인 · 취소 | US-025, D-128 |

## 1. 화면 목록

화면은 **로그인 · 홈 · 식품 등록 · 식품 상세 · 기록 · 음식추천 · 설정** 일곱 개이고, 화면 아래에 **홈 · 기록 · 음식추천 · 설정 탭**이 있다. 온보딩 화면은 만들지 않는다. (PRD 5-1, ARCH 2절, D-124, D-125)

| # | 화면 | 아래 탭 | 근거 |
|---|---|---|---|
| 1 | 로그인 (로그인 / 새 계정 만들기) | 없음 | US-012, D-080 |
| 2 | 홈 | 있음 (홈 탭) | US-007, US-008 |
| 3 | 식품 등록 — 등록 선택('사진으로 등록' / '직접 등록') · 직접 등록(규칙표에서 골라 등록 / 목록에 없는 식품 등록) · 사진으로 등록(사진 올리기 → 확인 화면 → 한꺼번에 등록) | 있음 | US-001, US-003, US-017 ~ US-020, D-100 |
| 4 | 식품 상세 (수정 · 보관 방법 바꾸기 · 다 먹음 / 버림 · 삭제를 모두 한다) | 있음 | US-004, US-005, US-006, US-011 |
| 5 | 기록 (숫자 · 처리한 식품 목록 · 홈으로 되돌리기) | 있음 (기록 탭) | US-013, US-015 |
| 6 | 음식추천 (끼니 · 음식 종류 고르기 · 추천 결과) | 있음 (음식추천 탭) | US-021, US-022 |
| 7 | 설정 (개인정보 안내 · 계정 탈퇴) | 있음 (설정 탭) | US-023 ~ US-025, D-125 |

## 3. 로그인 · 가입 (US-012)

### 3.1 목적
계정을 만들고 로그인해서, 로그인한 동안 내 식품만 본다. (US-012)

### 3.2 보여 주는 것
- 이메일 · 비밀번호 입력칸과 로그인 버튼. '새 계정 만들기'를 누르면 가입 입력으로 바뀐다. (시나리오 1, 2)
- 아래 탭과 로그아웃 버튼이 보이지 않는다. (D-080, D-130)
- 비밀번호 찾기 · 변경, 소셜 로그인, 이메일 인증은 없다. (D-048, D-050, D-051)

### 3.3 가입 (시나리오 1)

| 순서 | 사용자가 하는 일 | 화면에서 보이는 것 |
|---|---|---|
| 1 | '새 계정 만들기'를 누른다 | 이메일 · 비밀번호를 적는 칸 |
| 2 | 이메일과 비밀번호를 적고 가입을 누른다 | 이메일은 @ 와 점이 있는 모양, 비밀번호는 8자 이상이고 영문 · 숫자 · 특수문자를 모두 포함해야 한다 (D-046, D-047, D-095) |
| 3 | — | 가입되고 로그인된 상태로 **홈**이 보인다 (D-081). 처음 가입한 계정이면 기존 식품이 자동으로 옮겨져 홈에 보이고, 아니면 안내 문구와 식품 등록 버튼이 보인다 (D-042, D-043, D-044) |

**예외**

| 상황 | 화면 동작 | 근거 |
|---|---|---|
| 비밀번호가 규칙에 맞지 않음 | "비밀번호는 8자 이상이고 영문·숫자·특수문자를 모두 넣어 주세요." 가입되지 않음 | D-047 |
| 이미 가입된 이메일 | "이미 가입된 이메일이에요." 가입되지 않음 | D-058 |
| 기존 식품을 옮기다 실패 | 가입과 로그인은 된다. 옮기기는 전부 취소되어 일부만 옮겨진 채 남지 않고, 첫 계정이 다음에 로그인할 때 다시 시도한다 | D-096 |
| 가입 처리 실패 | 공통 규칙 (오류 알림). 입력한 내용은 그대로 | OQ-04 |

### 3.4 로그인 (시나리오 2)

| 순서 | 사용자가 하는 일 | 화면에서 보이는 것 |
|---|---|---|
| 1 | 이메일과 비밀번호를 적고 로그인을 누른다 | — |
| 2 | — | **홈**이 보인다. 내가 등록한 식품만 보인다 (D-081, D-061) |

**예외**

| 상황 | 화면 동작 | 근거 |
|---|---|---|
| 이메일이나 비밀번호가 틀림 | "이메일 또는 비밀번호가 맞지 않아요." 어느 쪽이 틀렸는지 알리지 않는다. 틀려도 횟수 제한은 없다 | D-057, D-049 |
| 로그인 처리 실패 | 공통 규칙 (오류 알림). 입력한 내용은 그대로 | OQ-04 |

### 3.5 로그아웃과 만료 (시나리오 3)

| 상황 | 사용자가 하는 일 | 화면 동작 | 근거 |
|---|---|---|---|
| 로그아웃 | 로그인 화면을 뺀 아무 화면에서나 맨 위 오른쪽의 로그아웃 버튼을 누른다 | 로그인 화면으로 간다. 이 기기만 로그아웃되고 다른 기기는 유지된다. 다시 로그인하기 전에는 식품이 보이지 않는다 | D-054, D-060, D-130 |
| 30분 동안 쓰지 않음 | 앱을 다시 쓰려 한다 | 로그인 화면으로 간다. 입력하던 내용은 사라진다. 다시 로그인하면 홈으로 간다 | D-052, D-055, D-056 |
| 로그인하지 않은 채 주소를 직접 열기 | 앱 안의 화면 주소를 직접 쓴다 | 로그인 화면으로 간다 | D-059 |

## 4. 홈 (US-007, US-008)

### 4.1 목적
사용자가 글을 읽지 않고 색과 막대로 냉장고 상태를 안다. (PRD 3절 목표 1)

### 4.2 보여 주는 것
- 이번 주 7일 달력 (일요일 시작) (US-007)
- 식품별 막대와 오늘을 가리키는 세로선 (US-007)
- 막대는 구매일부터 권장 기한까지 그린다. 이번 주를 넘는 막대는 시작과 끝을 잘라 이번 주 부분만 보여 준다. (US-007, OQ-07)
- 달력 아래 목록: 모든 식품이 같은 색 띠와 남은 날 · 지난 날 글자로 보인다. (ARCH 2절, 시나리오 4)
- 막대 색 (API 가 준 상태 값을 색으로만 표시) (D-009)

| 상태 | 색 | 기준 | 근거 |
|---|---|---|---|
| 여유 | 🟢 초록 | 기한까지 6일 이상 | US-008, D-014 |
| 주의 | 🟡 노랑 | 남은 기간 3~5일 | US-008, D-014 |
| 임박 | 🔴 빨강 | 남은 기간 0~2일 (기한 당일 포함) | US-008, D-014 |
| 지남 | ⚫ 검정 | 기한 다음 날부터 | US-008, D-014 |

### 4.3 목록 규칙
- 기한이 임박한 순으로 보인다. 기한이 같으면 구매일이 이른 식품이 먼저, 그것도 같으면 이름순이다. (US-007, D-015)
- ⚫ 지남 식품은 사용자가 처리할 때까지 홈에 남는다. 지난 지 4일 이상인 식품은 달력에서만 빠지고 목록에는 남는다. (US-008, D-014)
- 다 먹음 · 버림 식품은 홈에 나오지 않는다. (US-011, D-090)
- 지난주에 기한이 끝난 식품, 다음 주에 산 식품도 위 규칙과 같은 색 규칙을 따르며 별도 표시는 없다. (OQ-12)
- 같은 이름의 식품을 여러 번 사서 따로 둘 수 있다. (D-030)

### 4.4 사용자 행동
- 막대와 색을 보고 곧 끝나는 식품을 찾는다.
- 달력 막대나 목록의 식품을 누르면 식품 상세로 간다. (시나리오 10)

### 4.5 상태

| 상태 | 화면에 보이는 것 | 근거 |
|---|---|---|
| 식품 있음 | 4.2 ~ 4.3 | US-007 |
| 식품 없음 | 안내 문구 + 식품 등록 버튼 | OQ-05, US-007 |
| 불러오기 실패 | 실패했다는 쉬운 오류 메시지가 화면 위에 보임 | OQ-04, US-007 |

## 5. 식품 등록

### 5.0 등록 선택 (US-001, US-017)

**진입**: 홈이나 안내 문구 화면의 식품 등록 버튼을 누른다. (시나리오 5)

**보여 주는 것**
- **'사진으로 등록'과 '직접 등록'** 두 버튼. (D-100)
- '사진으로 등록' 버튼 아래에 작고 연한 글씨로 "AI 가 사진에서 식품 목록을 줘요"라는 안내 한 줄. (D-105)
- 아래 탭과 로그아웃 버튼이 보인다. (D-080, D-130)

**동작**
- '직접 등록'을 누르면 이름을 검색하는 화면으로 간다. 지금까지의 등록 과정(5.1, 5.2)이다. (D-100)
- '사진으로 등록'을 누르면 사진을 고르는 화면으로 간다. (5.3)

**상태**

| 상태 | 화면에 보이는 것 | 근거 |
|---|---|---|
| 처음 열림 | 두 버튼 + AI 안내 한 줄 | D-100, D-105 |
| 입력 중 | 해당 없음 (이 화면은 입력칸이 없다) | — |

### 5.1 규칙표에서 골라 등록 — 직접 등록 (US-001)

**입력 항목과 순서** (시나리오 6)
1. 식품 이름 검색 — 규칙표의 이름과 별칭에 검색어가 들어 있으면 찾는다. 예: "양" → 양파, 양배추. 오타 보정은 없다. (D-035)
2. 검색 결과에서 식품 선택
3. 수량과 단위 — 수량은 0보다 큰 숫자(소수 둘째 자리까지), 단위는 글자로 직접 적는다. 예: 1봉, 500g, 3개 (OQ-03, D-027)
4. 구매일 — 기본은 오늘, 미래 날짜도 가능 (US-001, OQ-03)
5. 보관 방법 — 상온 / 냉장 / 냉동. 식품을 고르면 규칙표의 기본값이 미리 선택되고 바꿀 수 있다. 그 식품에 쓸 수 없는 방법은 흐리게 보이고 고를 수 없다. (US-001, OQ-02, D-005)
6. 등록 버튼

**동작**
- 화면이 수량 · 단위가 채워졌는지 미리 확인한다. (D-010)
- API 가 다시 확인하고 권장 기한을 규칙표로 계산해 **내 식품으로** 저장한다. 권장 기한은 구매일 + 그 보관 방법의 기간이다. (US-001, ARCH 7-1)
- 구매일이 기한보다 뒤가 되는 조합은 저장하지 않는다. (D-003)
- 성공하면 홈으로 돌아가고 식품이 막대로 나타난다. (US-001)

**예외**

| 상황 | 화면 동작 | 근거 |
|---|---|---|
| 검색 결과 없음 | 결과가 없다는 표시 + 목록에 없는 식품 등록으로 갈 수 있음 | US-001 |
| 수량 · 단위가 비었음 / 수량이 0 이하 / 숫자가 아님 | 등록되지 않고 입력칸 옆에 안내가 보임 | US-001, OQ-03 |
| 저장 실패 | 공통 규칙 (오류 알림) | OQ-04 |
| 입력하다가 아래 탭을 누름 | "입력한 내용이 사라진다"는 확인 창. 입력한 것이 없으면 확인 창 없이 이동 | D-083, D-084 |

### 5.2 목록에 없는 식품 등록 — 직접 등록 (US-003)

**진입**: 이름 검색 결과가 없을 때만 연결된다. 다른 경로는 없다. (US-001, 시나리오 7)

**입력 항목과 순서** (시나리오 7)
1. 이름
2. 보관 방법 (상온 / 냉장 / 냉동 모두 가능)
3. 수량과 단위
4. 구매일 (기본 오늘)
5. 기한 — 날짜로 고르거나, 며칠 뒤인지 숫자로 적는다. (US-003)
6. 등록 버튼

**동작**
- "며칠 뒤"를 적으면 기한은 구매일 + N일이다. (D-002)
- 직접 적은 기한이 그대로 쓰인다. (US-003)
- API 가 이름 · 수량 · 단위 · 기한을 확인하고 **내 계정의 식품으로만** 저장한다. 공통 규칙표에는 더하지 않고 다른 계정에서는 보이거나 검색되지 않는다. (D-091)
- 기한은 오늘보다 과거이거나 구매일보다 앞이면 안 된다. (US-003, D-003)
- 성공하면 홈으로 돌아가고 직접 적은 기한의 막대가 나타난다. (US-003)

**예외**

| 상황 | 화면 동작 | 근거 |
|---|---|---|
| 기한이 비었음 / 오늘보다 과거 | 등록되지 않고 안내가 보임 | US-003, OQ-03 |
| 기한이 구매일보다 앞섬 | 등록되지 않고 안내가 보임 | D-003 |
| 수량 · 단위 오류 | 5.1 과 같음 | US-001 |
| 저장 실패 | 공통 규칙 (오류 알림) | OQ-04 |
| 입력하다가 아래 탭을 누름 | 5.1 과 같음 | D-083, D-084 |

### 5.3 사진으로 등록 — 사진 올리기와 식품 목록 받기 (US-017, US-018)

**진입**: 등록 선택 화면에서 '사진으로 등록'을 누른다. (시나리오 8)

**보여 주는 것**
- 사진을 고르는 곳. 사진은 **한 번에 한 장**이다. (D-101)
- 사진을 고른 뒤 올리는 버튼.
- '사진으로 등록' 버튼 아래의 AI 안내 한 줄은 5.0 에서 이미 보였다. (D-105)

**동작**
1. 사진을 고르면 화면이 jpg · png · webp, 5MB 이하, 한 장인지 미리 확인한다. 맞지 않으면 올라가지 않고 안내가 보인다. (D-101, ARCH 2절, 6절 V-23)
2. 올리기 버튼을 누르면 처리 중 표시가 보이고, 끝날 때까지 올리기 버튼을 다시 누를 수 없다. (D-112)
3. 올린 사진은 AI 가 읽는 동안만 쓰이고 저장되지 않는다. (D-102)
4. 읽기가 끝나면 **가공하지 않은 신선식품만** 나열된 **확인 화면**(5.4)으로 간다. 바나나 · 양파처럼 상온에 두는 신선식품도 나오고, 어묵 · 김치 · 햄 · 밀키트 · 통조림 · 냉동만두 같은 가공식품과 과자 · 음료 · 라면 · 생활용품은 나오지 않는다. (D-103)
5. 줄마다 이름 · 권장 보관 방법 · 방법별 최대 보관기간 · 금지된 보관 방법이 보인다. 식품 이름이 규칙표에 이미 있으면 규칙표 값을, 없으면 AI 가 알려 준 값을 보인다. (D-104, D-135)
6. 구매일은 영수증에서 읽은 날짜가 기본이고, 읽지 못하면(장바구니 사진 등) 오늘이다. (D-106, D-107)

**상태**

| 상태 | 화면에 보이는 것 | 근거 |
|---|---|---|
| 처음 열림 | 사진을 고르는 곳 | US-017 |
| 입력 중 | 사진을 고른 상태. 아래 탭을 누르면 5.1 과 같은 확인 창 | ARCH 2절 |
| 처리 중 | 처리 중 표시. 올리기 버튼은 누를 수 없다 | D-112 |
| 성공 | 확인 화면 (5.4) | US-018 |
| 입력 오류 | 사진이 아님 · 너무 큼 · 두 장 이상 → 올라가지 않고 안내가 보인다 | D-101 |
| 빈 결과 | 식품을 읽지 못했거나 신선식품이 하나도 없음 → 읽지 못했다는 안내와 함께 등록 선택 화면으로 돌아가 직접 등록으로 갈 수 있다. 실패가 아니다 | US-017, US-018 |
| 실패 | AI 가 응답하지 못함 → "AI 가 응답하지 못했어요. 다시 시도해 주세요." 올린 사진은 화면에 그대로 남아 다시 시도할 수 있다 | OQ-04, ARCH 3절 |

### 5.4 확인 화면과 한꺼번에 등록 (US-019, US-020)

**진입**: 사진 읽기가 끝나면 열린다. (시나리오 9)

**보여 주는 것**
- 나열된 식품 줄 목록. 처음에는 모든 줄이 등록 대상으로 선택돼 있다. (D-109)
- 줄 하나(나열된 식품 줄)에는 이름 · 수량 · 단위 · 구매일 · 보관 방법 · 기한 · 빼기가 있다. 줄은 휴대폰 화면에서 보기 쉽게 한 줄에 카드 한 장으로 보인다. (13.1 의 11번)
- 보관 방법은 권장 보관 방법이 미리 선택돼 있고, 방법마다 최대 보관기간이 보인다. 금지된 보관 방법은 흐리게 보이고 고를 수 없다. (D-004, D-005, D-104)
- 보관 방법을 바꾸면 그 방법의 최대 보관기간으로 기한이 다시 보인다. (US-019)
- '한꺼번에 등록' 버튼.

**동작**
- 줄마다 이름 · 수량 · 단위 · 구매일 · 보관 방법을 고칠 수 있고, 등록하지 않을 줄은 뺄 수 있다. (D-108)
- 수량 · 단위를 읽지 못해 비어 있으면 사용자가 적어야 한다. 입력 검사는 5.1 과 같다 (이름 · 수량 · 단위 필수, 수량은 0보다 큰 숫자). (D-108, US-001)
- 모든 줄을 빼면 '한꺼번에 등록'을 누를 수 없다. (US-019)
- '한꺼번에 등록'을 누르면 처리 중 표시가 보이고 버튼은 끝날 때까지 누를 수 없다. (D-112)
- API 가 줄마다 다시 확인하고 남긴 식품을 모두 **내 식품으로** 저장한다. 기한은 고른 보관 방법의 규칙표 기간으로 계산된다. 같은 이름의 줄이 여러 개면 따로 등록된다. 개수 상한은 없다. (D-030, D-111, D-134)
- 규칙표에 없던 이름의 식품은 이때 규칙표에 더해진다. 사용자가 뺀 식품은 더해지지 않는다. (D-136)
- 한 줄이라도 저장에 실패하면 **전부 취소**되어 아무것도 등록되지 않는다. (D-110)
- 성공하면 홈으로 돌아가고 식품이 막대로 나타난다. (US-020)
- 확인 화면에서 **이름을 고쳐 규칙표에 없게 된 줄**은 AI 가 알려 준 정보를 붙이지 않고, 그 줄에 기한 입력칸(기한 다시 적기)이 열린다. 사용자가 적은 기한으로 직접 등록 식품처럼 저장되고 규칙표에는 더해지지 않는다. 고친 이름이 규칙표에 있으면 규칙표 값을 쓴다. (ARCH 9절 25번, 13.2 의 1번)

**상태**

| 상태 | 화면에 보이는 것 | 근거 |
|---|---|---|
| 처음 열림 | 모든 줄이 선택된 목록 | D-109 |
| 입력 중 | 줄을 고치거나 뺀 상태. 아래 탭을 누르면 "입력한 내용이 사라진다"는 확인 창. 사용자가 고치거나 뺀 것이 없으면 확인 창 없이 이동한다 | D-083, D-084, ARCH 2절 |
| 처리 중 | 처리 중 표시. 한꺼번에 등록 버튼은 누를 수 없다 | D-112 |
| 성공 | 홈으로 이동. 식품이 막대로 나타남 | US-020 |
| 빈 결과 | 모든 줄을 뺌 → 한꺼번에 등록 버튼을 누를 수 없다 | US-019 |
| 입력 오류 | 이름 · 수량 · 단위가 비었음 / 수량이 0 이하·숫자가 아님 → 그 줄에 안내가 보이고 등록되지 않는다 | D-108 |
| 일부만 실패 | 전부 취소. 쉬운 오류 메시지가 보이고, 확인하던 목록과 고친 내용은 그대로 남아 다시 시도할 수 있다 | D-110, OQ-04 |
| 읽기 결과 만료 | "사진을 다시 올려 주세요." 확인하던 줄은 화면에 남지만 등록하려면 사진을 다시 올려야 한다 | ARCH 3절, 8절 |
| 저장 실패 | 공통 규칙 (오류 알림). 확인하던 목록은 그대로 | OQ-04 |

## 6. 식품 상세

**진입**: 홈에서 식품을 누른다. (시나리오 10)

### 6.1 보여 주는 것
- 이름, 구매일, 수량 · 단위, 보관 방법, 기한 (시나리오 10)
- 고친 내용과 새 기한이 상세에 보인다. (시나리오 11, 12)
- 뒤로 가면 바로 전에 보던 화면으로 돌아간다. (D-085)

**예외**: 없는 식품이거나 이미 처리된 식품이거나 **다른 계정의 식품**이면 똑같이 "찾을 수 없는 식품" 쉬운 오류 메시지가 보인다. 그 식품이 있는지 알려 주지 않는다. (D-008, D-063, D-090)

### 6.2 정보 고치기 — 이름, 구매일, 수량 · 단위 (US-004)

**사용자 행동**: 항목을 고치고 저장을 누른다.

**동작**
- 구매일을 고침 → 기한이 구매일이 움직인 일수만큼 같이 옮겨진다. 직접 적은 기한은 그대로 둔다. 구매일이 직접 적은 기한보다 뒤가 되는 수정은 저장하지 않는다. 구매일은 미래 날짜도 허용한다. (US-004, D-003, D-024, OQ-11)
- 이름을 고침 → 규칙표에서 새 이름을 찾는다. (US-004)
  - 규칙표에 있음: 규칙표 기준으로 기한을 다시 계산한다. 직접 등록 식품도 마찬가지이며, 지금까지 쓴 수명 비율을 이어받고 소수 날짜는 내림한다. (D-004, D-026, OQ-11)
  - 규칙표에 없음: 같은 수정 화면에 기한 입력칸(기한 다시 적기)이 나타나고, 기한을 적어야 저장된다. 기한은 오늘보다 과거 날짜를 적을 수 없다. (OQ-10, OQ-11, 시나리오 11)
- 이름과 구매일을 한 번에 고치면 이름 규칙을 먼저 적용하고 그 기한에 구매일 이동을 적용한다. (D-026)
- 수량 · 단위를 고침 → 바뀐 수량 · 단위가 보인다. 기한과 상태는 그대로다. (US-004, D-027)
- 저장되면 홈으로 돌아가고 막대와 색이 바뀐 대로 보인다. (D-020, 시나리오 11)

**예외 (모두 저장되지 않고 안내가 보임)** (US-004, OQ-03)
- 이름이 비었음
- 수량이 0 이하이거나 숫자가 아님
- 구매일을 직접 적은 기한보다 뒤로 바꿈
- 이미 기한이 지난 식품을 규칙표에 없는 이름으로 바꿈 → 바꿀 수 없다는 안내 (OQ-11)
- 저장 실패 → 공통 규칙 (오류 알림) (OQ-04)
- 입력하다가 아래 탭을 누름 → 확인 창 (D-083, D-084)

### 6.3 보관 방법 바꾸기 (US-005)

**사용자 행동**: 보관 방법을 다른 것으로 바꾸고 저장을 누른다.

**동작**
- 규칙표가 "불가"로 정한 방법은 흐리게 보이고 고를 수 없다. API 도 거절한다. (D-005, ARCH 6절 V-04) 상세 화면은 직접 등록 식품이면 세 방법을 모두 쓸 수 있는 것으로 보고, 규칙표 식품(사진으로 등록한 식품 포함)이면 규칙표 검색에서 이름이 같은 항목의 불가 목록을 쓴다. 규칙표에서 이름을 못 찾으면 상세는 그대로 열고 흐리게 보이지 못하며, 저장할 때 API 가 거절한다. (D-134, 13.1 의 8번, 10번)
- 같은 보관 방법을 고르면 기한 그대로 성공 처리한다. (시나리오 12)
- 규칙표에 있는 식품: 새 기한을 다음 식으로 다시 계산한다. (D-006, US-005)

  > 새 남은 기간 = (1 − 지금까지 보관한 기간 ÷ 지금 보관 방법의 최대 보관 기간) × 새 보관 방법의 최대 보관 기간

  소수 날짜는 내림한다. (D-004) 구매일이 미래이면 보관한 기간은 0일이다. (D-022) 이미 기한이 지난 식품도 같은 식을 쓴다. (D-006)
- 규칙표에 없는 식품(직접 등록): 같은 수정 화면에 기한 입력칸(기한 다시 적기)이 나타나고, 기한을 적어야 저장된다. 기한은 오늘보다 과거 날짜를 적을 수 없다. (D-023, OQ-09, OQ-11, 시나리오 12)
- 저장되면 홈으로 돌아가고 막대와 색이 바뀐다. (D-020, US-005)

**예외**
- "불가" 방법은 고를 수 없다. (D-005)
- 이미 기한이 지난 식품인데 계산 결과가 음수이거나 새 기한이 오늘보다 뒤가 되지 않음 → 보관 방법을 바꿀 수 없고 안내가 보인다. 새 기한이 오늘보다 뒤가 되면 바꿀 수 있고, 기한이 늘어나 더 이상 지남이 아니다. (D-006)
- 저장 실패 → 공통 규칙 (오류 알림) (OQ-04)

> 화면은 위 계산식을 직접 계산하지 않는다. 계산과 판정은 API 가 한다. (D-009, D-016)

### 6.4 다 먹음 / 버림 (US-011)

**사용자 행동**: '다 먹음' 또는 '버림'을 누르고, 확인 창에서 확인한다. (시나리오 13)

**동작**
- 확인하면 API 가 처리 상태(다먹음 / 버림)와 처리한 날짜(서버 한국 시간 오늘)를 저장한다. (D-064)
- 식품이 홈에서 빠진다. 처리한 식품은 데이터로 남아 **기록 화면**에서 숫자와 목록으로 볼 수 있다. (US-011, D-090)
- 홈에서는 되돌릴 수 없다. 잘못 눌렀으면 기록 화면에서 되돌린다. (D-072)
- 처리 후 홈으로 이동한다. (시나리오 13)

**예외**
- 확인 창에서 취소 → 아무것도 바뀌지 않는다.
- 마지막 식품을 처리해 홈이 비었음 → 홈에서 안내 문구와 식품 등록 버튼이 보인다. (OQ-05, US-011)
- 이미 처리되었거나 없는 식품에 요청이 옴 → 쉬운 오류 메시지 (D-008)
- 처리 실패 → 공통 규칙 (오류 알림). 아무것도 바뀌지 않는다. (OQ-04)

### 6.5 삭제 (US-006)

**사용자 행동**: 삭제를 누르고 확인 창에서 확인한다. (OQ-06)

**동작**
- 확인해야 지워진다. 삭제는 되돌릴 수 없다. (US-006, OQ-06)
- API 가 식품을 완전히 지운다. 기록에서도 지워진다. 버림은 기록에 남아서 다르다. (US-006, D-013, D-070, D-078)
- 홈으로 돌아가고 식품이 사라진다. (시나리오 14)

**예외**
- 확인 창에서 취소 → 아무것도 바뀌지 않는다. (시나리오 14)
- 마지막 식품을 삭제해 홈이 비었음 → 홈에서 안내 문구와 식품 등록 버튼이 보인다. (OQ-05, US-006)
- 이미 지워졌거나 없는 식품에 요청이 옴 → 쉬운 오류 메시지 (D-008)
- 삭제 실패 → 공통 규칙 (오류 알림) (OQ-04)

## 7. 기록 (US-013, US-015)

### 7.1 목적
내가 식품을 얼마나 먹고 버렸는지와 지금 냉장고가 어떤 상태인지를 숫자로 안다. 잘못 처리한 식품은 여기서 홈으로 되돌린다. (US-013, US-015)

**진입**: 아래 탭의 '기록'을 누른다. (시나리오 15)

### 7.2 숫자 다섯 가지 (모두 로그인한 내 식품만)
숫자는 API 가 세어 주고, 화면은 보여 주기만 한다. (D-009)

| # | 이름 | 센 것 | 근거 |
|---|---|---|---|
| 1 | 다 먹음 | 처리 상태가 다먹음인 식품 수. **올해**와 **이번 달** 두 가지로 보인다 | D-065, D-066 |
| 2 | 버림 | 처리 상태가 버림인 식품 수. **올해**와 **이번 달** 두 가지로 보인다 | D-065, D-066 |
| 3 | 현재 총 식품 종류 | 지금 냉장고에 있는(다먹음·버림이 아닌) 식품이 몇 종류인지. 같은 이름은 한 종류로 센다 | D-067 |
| 4 | 보관 상태별 식품 수 | 지금 있는 식품을 상온 / 냉장 / 냉동 별로 센 수 | D-068 |
| 5 | 식품 상태별 식품 수 | 지금 있는 식품을 🟢 여유 / 주의 / 🔴 임박 / ⚫ 지남 별로 센 수. 색은 홈과 같다 | D-069, D-009 |

- "올해 · 이번 달"은 처리한 날짜 기준이고, 서버 한국 시간으로 센다. (D-066, D-088)
- 삭제한 식품은 어떤 숫자에도 들어가지 않는다. (D-070)
- 로그인이 없던 때 처리한 기존 식품은 옮겨 온 날을 처리한 날로 센다. (D-045)

### 7.3 처리한 식품 목록 (US-015)
- 숫자 아래에 처리한 식품 목록이 보인다. **전체**, **최근 처리한 순**이다. (D-073)
- **다 먹음과 버림을 나눠서** 보인다. (D-074)
- 한 줄에 **이름 · 수량 · 처리한 날짜**가 보인다. (13.1 의 5번)
- 각 식품에 '홈으로 되돌리기' 버튼이 있다. (시나리오 16)

### 7.4 홈으로 되돌리기 (시나리오 16)

**사용자 행동**: 처리한 식품 목록에서 식품을 골라 '홈으로 되돌리기'를 누른다.

**동작**
- 식품이 목록에서 빠지고, 기록 숫자(올해 · 이번 달)에서도 빠진다. 홈에는 다시 나타난다. (D-075)
- 이름 · 수량 · 단위 · 구매일 · 보관 방법 · 기한은 처리하기 전 그대로다. 처리한 날짜는 지워진다. (D-075, D-076)
- 기한이 지난 뒤 처리했던 식품은 되돌리면 기한과 오늘 날짜로 다시 판정해 ⚫ 지남으로 보이고, 처리할 때까지 목록에 남는다. (D-077)
- 삭제한 식품은 기록에도 없으므로 되돌릴 수 없다. (D-078)

### 7.5 상태

| 상태 | 화면에 보이는 것 | 근거 |
|---|---|---|
| 숫자 있음 | 7.2 의 숫자 다섯 가지 + 7.3 의 처리한 식품 목록 | US-013 |
| 다 먹음 · 버림 · 현재 식품이 모두 없음 | 모든 숫자가 0 으로 보이고 안내 문구와 식품 등록 버튼이 함께 보임 | D-071, OQ-23 |
| 처리한 식품이 하나도 없음 | 되돌릴 식품이 없다는 안내 | US-015 |
| 숫자를 불러오지 못함 | 쉬운 오류 메시지가 화면 위에 보임 | OQ-04, US-013 |
| 되돌리기 실패 | 쉬운 오류 메시지가 보이고 아무것도 바뀌지 않음. 다시 시도할 수 있음 | OQ-04, 시나리오 16 |

## 8. 음식추천 (US-021, US-022)

### 8.1 목적
냉장고 속 식품을 버리지 않고 쓰기 위해, 지금 가진 식품으로 만들 수 있는 음식을 AI 에게 추천받는다. (US-021)

**진입**: 아래 탭의 '음식추천'을 누른다. (시나리오 17)

### 8.2 보여 주는 것
- **끼니** 고르기: 아침 / 점심 / 저녁 중 하나. (D-116)
- **음식 종류** 고르기: 양식 / 한식 / 일식 / 중식 / 간단히 / 직접 입력 중 하나. (D-117)
- '직접 입력'을 고르면 원하는 음식 종류(예: 국물 요리)를 적는 글자 입력칸이 생긴다. (D-118)
- '추천받기' 버튼.
- 추천 결과: **음식 카드** 최대 3개. 카드마다 음식 이름과 재료가 보이고, 재료는 가진 것과 지금 없는 것을 구분해서 보인다. 만드는 법은 없다. (D-113, D-115, D-121, 13.1 의 12번)

### 8.3 동작
1. 끼니와 음식 종류를 하나씩 고르고 추천받기를 누른다. '직접 입력'이면 글자를 적어야 한다. (D-116 ~ D-118)
2. 처리 중 표시가 보이고, 끝날 때까지 추천받기 버튼을 다시 누를 수 없다. (D-112)
3. API 가 **내 식품 중 처리하지 않았고 기한이 지나지 않은 것**을 재료로 AI 에게 보내 음식을 추천받는다. (D-120)
4. 내 식품이 재료로 **2개 이상** 들어가는 음식만 나온다. (D-119)
5. **기한이 임박한 식품을 먼저 쓰는 음식**이 앞에 나온다. (D-114)
6. 음식은 최대 3개이고, 각 음식에서 지금 없는 재료는 따로 표시된다. (D-113, D-115)
7. 끼니나 음식 종류를 바꿔 다시 추천받을 수 있다. 횟수 제한은 없다. 고르는 항목이 있어서 매일 같은 음식만 나오지 않는다. (D-123)
8. 추천 결과는 저장하지 않는다. 화면을 나가면 사라지고 다시 보려면 다시 추천받는다. (D-122)

### 8.4 상태

| 상태 | 화면에 보이는 것 | 근거 |
|---|---|---|
| 처음 열림 | 끼니 · 음식 종류를 고르는 곳과 추천받기 버튼. 추천 결과는 비어 있다 | US-022 |
| 입력 중 | 끼니 · 음식 종류를 고르는 중. 이 화면은 입력 중 이동 확인 창을 띄우지 않는다 (D-083 은 식품 등록 · 수정 화면만 말한다) | D-083 |
| 처리 중 | 처리 중 표시. 추천받기 버튼은 누를 수 없다 | D-112 |
| 결과 있음 | 음식 카드 최대 3개 | US-021 |
| 빈 결과 (식품 없음) | 추천할 재료가 없다는 안내와 식품 등록 버튼 | OQ-05, US-021 |
| 빈 결과 (맞는 음식 없음) | 재료가 2개 이상 들어가는 음식을 찾지 못함 → 추천할 음식이 없다는 안내 | D-119, US-021 |
| 입력 오류 | 끼니나 음식 종류를 고르지 않음 / '직접 입력'을 골랐는데 비워 둠 → 추천받기를 누를 수 없거나 고르라는 안내가 보인다 | US-021 |
| 실패 | AI 가 응답하지 못함 → "AI 가 응답하지 못했어요. 다시 시도해 주세요." 고른 끼니와 음식 종류는 그대로 남아 다시 시도할 수 있다 | OQ-04, ARCH 3절 |

## 9. 설정 (US-023 ~ US-025)

### 9.1 목적
개인정보 안내를 읽고, 계정을 탈퇴한다. 계정에 관한 일을 한곳에 모았다. (US-023, D-125)

**진입**: 아래 탭의 '설정'을 누른다. (시나리오 18)

### 9.2 보여 주는 것
- **개인정보 안내** 항목. 눌러서 안내문구를 연다. (US-024, D-125, 13.1 의 14번)
- **[계정 탈퇴]** 버튼. (D-089)
- 맨 위 오른쪽에 로그아웃 버튼 (모든 화면 공통). (D-130)
- 기한 기준 조절 같은 다른 설정은 없다. (PRD 5-3)

| 2 | 올린 사진은 저장하지 않고, 읽는 동안만 쓴다 | D-102, D-126 |
| 3 | 사진과 식품 정보가 AI 로 읽거나 추천하는 일에 쓰인다 | D-126 |
| 4 | 탈퇴하면 계정과 식품이 모두 삭제된다 | D-127, D-126 |

**동작**: 문구는 쓰는 쪽이 초안을 쓰고 사용자가 확인해 확정한다. 안내문구는 앱에 들어 있는 글이라 비거나 불러오지 못하는 경우가 없다. (D-126, US-024)

### 9.4 계정 탈퇴 (US-025)

**사용자 행동**: [계정 탈퇴]를 누르고, 확인 창에서 비밀번호를 다시 적고 확인한다. (시나리오 19)

**동작**
1. [계정 탈퇴]를 누르면 **탈퇴 확인 창**이 보인다. 삭제는 되돌릴 수 없다는 안내와 비밀번호를 적는 칸이 있다. (D-128)
2. 비밀번호를 적고 확인하면 처리 중 표시가 보이고, 끝날 때까지 탈퇴 버튼을 다시 누를 수 없다. (D-112)
3. 비밀번호가 맞으면 **계정과 식품이 모두 삭제된다.** 다 먹음 · 버림으로 처리한 식품(기록)도 지워진다. (D-127)
4. 이 계정의 로그인은 모든 기기에서 끝나고 로그인 화면으로 간다. (D-129)
5. 취소하면 아무 일도 없다. (시나리오 19)
6. 탈퇴한 이메일로 다시 가입하면 새 계정이 만들어지고 식품이 하나도 없는 상태로 시작한다. (US-025)

**상태**

| 상태 | 화면에 보이는 것 | 근거 |
|---|---|---|
| 처음 열림 | 개인정보 안내 항목과 [계정 탈퇴] 버튼 | US-023 |
| 입력 중 | 탈퇴 확인 창에서 비밀번호를 적는 중 | D-128 |
| 처리 중 | 처리 중 표시. 탈퇴 버튼은 누를 수 없다 | D-112 |
| 성공 | 로그인 화면으로 이동. 이 계정의 모든 기기 로그인이 끝남 | D-129 |
| 입력 오류 | 비밀번호를 틀리게 적거나 비움 → 탈퇴되지 않고 안내가 보인다. 비밀번호를 맞게 다시 적어야 한다 | D-128 |
| 실패 | 쉬운 오류 메시지가 보이고 **아무것도 지워지지 않은 상태**로 남아 다시 시도할 수 있다 | OQ-04 |

## 10. 아래 탭 (US-016)

### 10.1 보여 주는 것
- 화면 맨 아래에 **홈 · 기록 · 음식추천 · 설정** 탭이 있다. 지금 있는 화면의 탭이 눈에 띄게 표시된다. (D-124)
- 로그인 화면을 뺀 모든 화면(홈 · 기록 · 음식추천 · 설정 · 식품 등록 · 식품 상세)에서 보인다. (D-080)
- 식품이 없어도 탭은 보인다. (US-016)
- 휴대폰 화면 우선이라 화면 맨 아래에 붙는다. (PRD 2절)

### 10.2 동작 (시나리오 20)

| 순서 | 사용자가 하는 일 | 화면에서 보이는 것 | 근거 |
|---|---|---|---|
| 1 | 아래 탭의 '기록'을 누른다 | 기록 화면. 기록 탭이 눈에 띄게 표시된다 | D-124 |
| 2 | '홈'을 누른다 | 홈 화면 | D-124 |
| 3 | '음식추천'을 누른다 | 음식추천 화면 | D-124 |
| 4 | '설정'을 누른다 | 설정 화면 | D-124 |
| 5 | 지금 있는 탭을 다시 누른다 | 아무 일도 없다 (새로 불러오거나 맨 위로 가지 않는다) | D-082 |
| 6 | 식품 등록 · 수정 화면에서 입력하다가 탭을 누른다 | "입력한 내용이 사라진다"는 확인 창. 확인하면 이동하고 입력은 사라지며, 취소하면 그 화면에 남는다. 입력한 것이 없으면 확인 창 없이 바로 이동한다. "입력한 것"은 사용자가 적거나 바꾼 것을 말하고, 처음부터 채워진 기본값은 세지 않는다 | D-083, D-084 |
| 7 | 식품 상세 같은 하위 화면에서 뒤로 간다 | 바로 전에 보던 화면(홈 · 기록 · 음식추천 · 설정 중 하나). 브라우저의 뒤로가기 버튼은 정하지 않았다 | D-085 |

### 10.3 예외
탭을 눌렀는데 화면을 열지 못하면(식품 · 기록을 불러오지 못함) 쉬운 오류 메시지가 화면 위에 보인다. 지금 있던 화면은 그대로 남고, 같은 탭을 다시 눌러 다시 시도할 수 있다. (D-086)

| 종류 | 화면 동작 | 근거 |

| 입력 규칙 위반 (수량 비어 있음, 기한이 과거, 구매일이 기한보다 뒤, 비밀번호 규칙 등) | 입력칸 옆에 안내가 보이고 저장되지 않는다. 입력한 내용은 그대로 남는다. 화면을 거치지 않은 요청도 API 가 막는다 | ARCH 8절, D-010 |
| 선택 불가 보관 방법 | 화면에서는 흐리게 보여 고를 수 없고, API 도 거절한다 | D-005, ARCH 8절 |
| 저장 · 수정 · 처리 · 삭제 · 되돌리기 실패 | 실패했다는 쉬운 오류 메시지가 화면 위에 보인다. 입력한 내용은 그대로 남아 다시 시도할 수 있다 | OQ-04, ARCH 8절 |

| 없는 식품 / 이미 처리된 식품 / 다른 계정의 식품 | 모두 같은 "찾을 수 없는 식품" 메시지. 남의 식품이 있는지 알리지 않는다 | D-008, D-063 |
| 기한을 다시 적어야 함 | 실패가 아니다. 같은 화면에 기한 입력칸이 열린다 | OQ-09, OQ-10 |
| 로그인 안 함 · 30분 만료 | 로그인 화면으로 간다. 입력하던 내용은 사라진다 | D-055, D-059 |
| 로그인 틀림 | "이메일 또는 비밀번호가 맞지 않아요." | D-057 |

| AI 가 응답하지 못함 (사진 읽기 · 음식 추천) | "AI 가 응답하지 못했어요. 다시 시도해 주세요." 올린 사진과 고른 끼니 · 음식 종류는 그대로 남아 다시 시도할 수 있다 | OQ-04, ARCH 3절, 8절 |

| 사진 읽기 결과가 없거나 30분 지남 | "사진을 다시 올려 주세요." | ARCH 3절, 8절 |
| 한꺼번에 등록이 일부라도 실패 | 전부 취소되어 아무것도 등록되지 않는다. 확인하던 목록은 그대로 남는다 | D-110 |
| 탈퇴 비밀번호가 틀림 | 탈퇴되지 않고 안내가 보인다 | D-128 |
| 탈퇴 삭제 실패 | 쉬운 오류 메시지. 아무것도 지워지지 않는다 | OQ-04 |

- 버튼은 다시 누를 수 있게 돌아온다. (시나리오 21)
- 계속 실패하면 같은 오류 메시지가 계속 보인다. 문의 방법 같은 추가 안내는 범위 밖이다. (시나리오 21)

## 13. 정한 것과 남은 확인 (프론트엔드)

서버 쪽 일은 넣지 않고, 화면이 서버에 기댈 부분만 적었다.

### 13.1 정한 것

| # | 항목 | 정한 내용 | 이유 | 근거 |
|---|---|---|---|---|
| 1 | 기존 홈 · 등록 · 상세 화면 코드 | 이어서 쓰고 새 화면(등록 선택 · 사진으로 등록 · 확인 화면 · 음식추천 · 설정)만 더한다 | 기존 세 화면의 동작 규칙은 대부분 그대로라서, 새로 만들면 이미 확인한 동작을 다시 확인해야 한다 | 사용자 결정 |
| 2 | 로그인 상태를 서버에 보여 주는 방식 | 쿠키 방식. 서버 담당과 맞춘다 | 서버가 로그인 상태를 기억하고 요청마다 마지막 사용 시각을 갱신하므로(D-094), 브라우저가 요청마다 알아서 같이 보내는 쿠키가 화면 코드를 가장 덜 건드린다. 서버와 방식이 다르면 로그인이 안 되므로 맞춰야 한다 | 사용자 결정, D-094 |
| 3 | 서버에 아직 없는 창구 | 서버가 준비될 때까지 가짜 데이터(mock)로 화면을 먼저 확인한다. 새 창구(사진 읽기 · 한꺼번에 등록 · 음식 추천 · 탈퇴)도 같다 | 화면을 서버 완성을 기다리지 않고 만들 수 있다. 서버가 준비되면 실제 서버로 다시 확인한다 | 사용자 결정 |
| 4 | 브라우저 뒤로가기 버튼 | 앱 안에서 바로 전 화면으로 가는 것까지만 한다 | 브라우저 버튼의 동작은 문서에 정해진 것이 없다. D-085 는 앱 안의 "뒤로"만 정했다 | 사용자 결정, D-085 |
| 5 | 처리한 식품 목록에 보일 칸 | 이름 · 수량 · 처리한 날짜 | 무엇을, 얼마나, 언제 처리했는지 알면 되돌릴 식품을 고를 수 있다 | 사용자 결정, D-073, D-075 |
| 6 | "입력한 것이 있다"의 기준 | 사용자가 적거나 바꾼 것이 있을 때만 입력으로 본다 | 구매일 기본값(오늘)처럼 처음부터 채워진 값만 있으면 잃을 내용이 없다. 이때 확인 창을 띄우면 D-084 의 취지에 어긋난다 | 사용자 결정, D-083, D-084 |
| 7 | 다 먹음 · 버림의 확인 창 | 확인 창을 띄운다 (0절, 6.4) | 처리는 홈에서 되돌릴 수 없어서(D-072) 잘못 누르는 것을 막아야 한다. 시나리오 13 의 "처리 확인"도 이 확인 창을 뜻하는 것으로 본다. 다만 PRD · DECISIONS · USER-WORKFLOW 의 확인 창 설명에는 삭제 · 탭 이동 · 탈퇴만 적혀 있어, 이 문서들에 처리 확인 창을 더해야 한다 | 사용자 결정, 시나리오 13, D-072 |
| 8 | 상세 화면의 보관 방법별 가능 여부 | 지금 방식을 유지한다. 상세를 연 뒤 직접 등록 식품은 세 방법 모두 쓸 수 있는 것으로 보고, 규칙표 식품(사진으로 등록한 식품 포함)은 규칙표 검색에서 이름이 같은 항목의 불가 목록으로 흐리게 보인다 (6.3) | 식품 한 건의 응답 칸(ARCH 3절)에는 가능 여부가 없고 규칙표 검색 결과에만 있다. 이 방식은 서버를 바꾸지 않고 화면에서 이미 풀어 둔 것이라 그대로 쓰는 것이 가장 덜 건드린다 | 사용자 결정(문서 확인), D-005, D-134, ARCH 3절 |
| 9 | 안내 · 오류 문구 | 이미 정해진 문구(ARCH 3절의 로그인 실패 · 중복 이메일 · 비밀번호 규칙 · 찾을 수 없는 식품 · AI 응답 실패 · 사진 읽기 결과 만료 · AI 안내 한 줄)와 쓰던 기본 문구를 따른다. 기록 · 로그인 화면 · 탭 · 처리 확인 창 · 되돌리기 · 음식추천 · 설정 · 탈퇴의 새 문구는 구현할 때 쉬운 말로 제안해서 확인받는다. 처리 확인 창에는 "되돌릴 수 없어요"를 쓰지 않는다 (기록에서 되돌릴 수 있다, D-072). 탈퇴 확인 창에는 "되돌릴 수 없다"를 쓴다 (D-127) | 문구는 구현 단계에서 정하기로 했다 | 사용자 결정(문서 참조), OQ-03, ARCH 3절 |
| 10 | 상세에서 규칙표 식품의 이름을 규칙표에서 못 찾을 때 | 상세는 열고, 불가 보관 방법은 흐리게 보이지 못하는 대신 저장할 때 API 가 거절한다 | 규칙표 내용이 바뀌어 이름을 못 찾을 수 있다(13.1 의 8번). 이때 상세를 "불러오기 실패"로 막으면 식품을 고치지도 지우지도 못한다. 최종 판단은 API 가 한다(D-010) | 사용자 결정, D-010 |
| 11 | 확인 화면의 줄 표시 | 식품 한 개를 카드 한 장으로 보인다. 카드에 이름 · 수량 · 단위 · 구매일 · 보관 방법(방법마다 최대 보관기간) · 기한 · 빼기를 둔다 | 휴대폰 화면을 우선으로 하므로(PRD 2절) 표보다 카드가 보기 쉽다. 줄마다 고치고 뺄 수 있어야 한다(D-108) | 사용자 결정, D-104, D-108 |
