# SCENARIO-REVIEW: 냉장고 관리 웹 앱

검수자가 화면에서 눈으로 확인할 시나리오 표다. PRD 의 Must 완료 조건마다 한 줄이고, 상태가 바뀌는 시나리오의 "새로고침 뒤" 줄은 아래 별도 섹션에 모았다.
근거: [prd.md], [USER-WORKFLOW.md], [SCREEN-SPEC.md], [API-SPEC.md], [DECISIONS.md]. 

## 읽는 법

- 열: 번호 · 시나리오 · 행동 · 기대 결과 · 근거 · 실제 결과 · 판정
- 근거는 요구사항 ID(R-, US-), 결정 번호(D-), PRD 열린 질문(OQ-), 시나리오 번호(USER-WORKFLOW), 다른 기준 문서에만 정해진 내용은 문서와 절(예: SCREEN-SPEC 11.1)이다.
- 모든 줄은 로그인한 상태에서 한다(D-059). 가입 · 로그인 · 로그아웃을 확인하는 줄은 행동 칸에 적은 상태에서 시작한다.
- 화면만으로 볼 수 없는 줄은 행동에 "개발자 도구" 또는 "DB"를 적었다. 어떻게 확인할지는 아래 "필요 질문"에 남겼다.
- 판정 값은 `통과 / 차이 / 발견 기록` 중 하나다. 
- 새로고침 = 브라우저 새로고침.

| 로그인 필요 | 다시 로그인해 주세요. | 로그인하지 않았거나 30분이 지나 만료된 요청일 때. 화면은 로그인 화면으로 간다 (D-059, API-SPEC 3절, SC-62 · 65) |
| 이미 가입된 이메일 | 이미 가입된 이메일이에요. | 이미 가입된 이메일로 가입할 때 (D-058, API-SPEC 3절, SC-55) |
| 비밀번호 규칙 | 비밀번호는 8자 이상이고 영문·숫자·특수문자를 모두 넣어 주세요. | 가입할 때 비밀번호가 8자 미만이거나 영문 · 숫자 · 특수문자 중 빠진 것이 있을 때 (D-047, API-SPEC 3절, SC-53) |

정상이 아닐 때 공통으로 지켜야 하는 것 (SCREEN-SPEC 0절 · 9절, USER-WORKFLOW 시나리오 15)

- 입력 오류는 입력칸 옆에 보이고, 저장 · 수정 · 처리 · 삭제 · 되돌리기 · 불러오기 실패는 화면 위에 보인다.
- 아무것도 바뀌지 않는다. 식품이 만들어지거나 바뀌거나 지워지지 않는다.
- 입력한 내용은 그대로 남고, 버튼은 다시 누를 수 있게 돌아온다.
- 처리하는 동안에는 버튼이 잠겨 다시 누를 수 없다. 끝나거나 실패하면 다시 누를 수 있게 돌아온다. (D-100)
- 계속 실패하면 같은 메시지가 계속 보인다. 문의 방법 같은 추가 안내는 없다.

## 필요 질문
1. 30분 만료(SC-62 · 63)는 실제로 30분을 기다려 확인할지, DB 의 마지막 사용 시각을 바꿔 확인할지 백엔드 담당이 정해 주어야 한다.
2. 올해 · 이번 달 세기(SC-72)와 처리한 날짜 순서(SC-77)는 DB 에서 처리한 날짜를 바꿔 확인해도 되는가? 1월에 검수하면 "올해의 지난달"을 만들 수 없다.
3. 기존 식품 옮기기(SC-51 · 52)를 확인하려면 "아직 아무도 가입하지 않은 DB"와 v0.2.0 SQLite 파일이 필요하다. 이 상태를 어떻게 준비하고, 옮기기 실패를 어떻게 일으킬지 백엔드 담당이 정해 주어야 한다.
4. 클라우드 DB 연결 실패(SC-82)를 어떻게 일으킬지 백엔드 담당이 정해 주어야 한다. "서버를 끈 채" 줄과는 다른 경우다.
5. 검수에 쓸 DB 는 실제 클라우드 DB 인가, 검수용으로 따로 만든 DB 인가?
