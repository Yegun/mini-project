# SCENARIO-REVIEW: 냉장고 관리 웹 앱

검수자가 화면에서 눈으로 확인할 시나리오 표다. PRD 의 Must 완료 조건마다 한 줄이고, 상태가 바뀌는 시나리오의 "새로고침 뒤" 줄은 아래 별도 섹션에 모았다.
근거: [prd.md](../기초문서/v0.3.0_PRD.md), [USER-WORKFLOW.md](../기초문서/v0.3.0_USER-WORKFLOW.md), [SCREEN-SPEC.md](../설계_문서/v0.3.0_SCREEN-SPEC.md), [API-SPEC.md](../설계_문서/v0.3.0_API-SPEC.md), [DECISIONS.md](../기초문서/v0.3.0_DECISIONS.md) (모두 v0.3.0). 이전 버전의 같은 문서는 `docs/version/0.2.0/product-review/` 에 있다.

## 읽는 법

- 열: 번호 · 시나리오 · 행동 · 기대 결과 · 근거 · 실제 결과 · 판정
- 근거는 요구사항 ID(R-, US-), 결정 번호(D-), 질문 번호(OQ-), 시나리오 번호(USER-WORKFLOW 의 "시나리오 N")다.
- 번호(SC-01 …)는 표를 가로질러 이어서 붙였다.
- 실제 결과와 판정 열은 2026-11-02 ~ 03 검수로 채웠다. 검수 방법과 한계는 맨 아래 "검수 기록"에 있다.
- 판정 값은 `통과 / 차이 / 발견 기록` 중 하나다.
- 새로고침 = 브라우저 새로고침.
- "서버를 끈 채" 줄은 브라우저의 API 요청을 끊어서 확인했다.
- v0.2.0 의 홈 · 등록 · 수정 · 보관 방법 · 처리 · 삭제 시나리오는 이어받았다. 로그인 · 내 식품 분리 · 기록 · 되돌리기 · 아래 탭 · 클라우드 저장은 새로 넣었다.

## 기본 메시지

| 메시지 | 기본 문구 | 나오는 때 |
|---|---|---|
| 로그인 틀림 | 이메일 또는 비밀번호가 맞지 않아요. | 이메일이나 비밀번호가 틀렸을 때 (어느 쪽인지 알리지 않음) |
| 다시 로그인 | 다시 로그인해 주세요. | 로그인하지 않았거나 30분이 지나 API 가 거절했을 때 |
| 이미 가입된 이메일 | 이미 가입된 이메일이에요. | 이미 있는 이메일로 가입하려 할 때 |
| 비밀번호 규칙 | 비밀번호는 8자 이상이고 영문·숫자·특수문자를 모두 넣어 주세요. | 가입할 때 비밀번호가 규칙에 맞지 않을 때 |
| 없는 식품 | 찾을 수 없는 식품이에요. | 없거나 이미 처리됐거나 다른 계정의 식품에 요청이 갔을 때 |
| 기한 다시 적기 | 기한을 다시 적어 주세요 (구현 단계에서 정한 문구를 따른다) | 직접 등록 식품의 보관 방법을 바꾸거나 이름을 규칙표에 없는 이름으로 바꿀 때. 실패가 아니라 입력칸이 열리는 것이다 |
| 저장 · 불러오기 실패 | 구현 단계에서 정한 쉬운 오류 문구 (한 가지로 통일) | 저장 · 수정 · 처리 · 삭제 · 되돌리기 · 가입 · 로그인이 안 됐거나 홈 · 기록을 못 불러왔을 때, DB 연결 실패 · 인터넷 없음 |
| 빈 홈 · 빈 기록 | 안내 문구 + 식품 등록 버튼 | 홈에 식품이 없을 때, 기록에서 다 먹음 · 버림 · 현재 식품이 모두 없을 때 |
| 처리한 식품 없음 | 되돌릴 식품이 없다는 안내 | 기록에 처리한 식품이 하나도 없을 때 |

정상이 아닐 때 공통으로 지켜야 하는 것 (SCREEN-SPEC 0절 · 9절, USER-WORKFLOW 시나리오 15)

- 입력 오류는 입력칸 옆에 보이고, 저장 · 수정 · 처리 · 삭제 · 되돌리기 · 불러오기 실패는 화면 위에 보인다.
- 아무것도 바뀌지 않는다. 식품이 만들어지거나 바뀌거나 지워지지 않는다.
- 입력한 내용은 그대로 남고, 버튼은 다시 누를 수 있게 돌아온다.
- 계속 실패하면 같은 메시지가 계속 보인다. 문의 방법 같은 추가 안내는 없다.
- 로그인 화면으로 가는 경우(로그인 안 함 · 30분 만료)는 입력하던 내용이 사라진다.
