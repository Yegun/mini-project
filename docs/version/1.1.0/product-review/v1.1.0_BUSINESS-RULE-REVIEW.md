# BUSINESS-RULE-REVIEW: 냉장고 관리 웹 앱

[DECISIONS.md](../../../../DECISIONS.md) 에서 v1.1.0 에 새로 생긴 결정(D-198 ~ D-206) 중 **규칙으로 확인해야 하는 것만** 골라 [SCENARIO-REVIEW](v1.1.0_SCENARIO-REVIEW.md)와 같은 열로 정리한 검수 표다. 화면만으로 볼 수 없는 것(이 기기에 남는 값, 서버 요청, 저장하지 못하는 환경)이 중심이다.
이전 버전의 같은 문서는 `docs/version/1.0.0/product-review/` 에 있다.

## 읽는 법

- 열: 번호 · 시나리오 · 행동 · 기대 결과 · 근거 · 실제 결과 · 판정
- 근거는 D-번호다. 번호는 v1.0.0 문서에서 이어서 붙였다 (BR-121 다음이 BR-122).
- 화면만으로 볼 수 없는 줄은 행동에 "개발자 도구" 또는 "터미널"을 적었다. 개발자 도구의 저장소는 브라우저 개발자 도구(F12) > Application > Local Storage 에서 본다.
- 이 기기에 남는 값 두 가지의 이름: `app.guidePending`(설명서를 보여 줄 차례. 가입한 이메일) · `app.guideAccount`(이 기기에서 지금 로그인한 계정의 이메일).
- 비밀 값(DB 주소 · AI 키)은 확인하는 사람도 화면과 채팅에 옮겨 적지 않는다. 이름이 있는지만 본다.
- 이메일은 확인용 가짜 주소(예: `check1@example.com`)를 쓴다. 실제 계정 이메일을 문서에 적지 않는다.
- 실제 결과와 판정 열은 검수하면서 채운다. 이번 검수에서는 모든 줄을 기대 결과와 같다고 보고 `통과` 로 적었다. 검수 전에는 `미검수` 였다.
- 판정 값은 `통과 / 차이 / 발견 기록` 중 하나다.

## 검수 기록

- 검수일: 2026-11-05
- 코드 상태: `test/v1.1.0` 브랜치, 커밋 `7db71ec` 기준 (작업 폴더에 바뀐 것 없음)
- 검수자: 사용자와 Claude. Claude 는 브라우저(Edge, 휴대폰 크기 390 x 844)를 직접 조종해서 화면 모양 · 움직임 · 기기에 남는 값을 확인했다. Claude 가 하지 못한 부분(BR-129, SC-170 의 빈 홈 안내, SC-180 의 사진 확인 화면 제목)은 사용자가 직접 확인했고 모두 기대대로라고 보고했다.
- 검수 환경: 개발 서버, 가짜 응답 모드(서버 없이 동작, 진짜 DB 에 계정을 만들지 않음). 운영 주소(Vercel)에서는 하지 않았다.
- 한계: 가짜 응답 서버의 홈은 식품이 들어 있어 "빈 홈 안내"를 Claude 가 못 봤다. 진짜 휴대폰의 손가락 조작은 터치 흉내로 대신했다. 사이트 데이터 차단은 저장소 읽기 · 쓰기를 오류로 만들어 흉내 냈다. 포인트 색 · 테마 조합의 모든 화면을 눈으로 보지는 않았고, 글자 대비는 값으로 계산했다. 설명서의 움직임은 시간별 캡처와 계산된 값으로 확인했고 사람이 보는 부드러움은 별도로 보지 못했다.
- 판정 값: `통과`(기대와 같음) · `차이`(기대와 다름) · `발견 기록`(문서에 없던 것을 발견하거나 그 줄의 행동을 그대로 할 수 없음).

결과 요약: 12줄 (BR-122 ~ BR-133) 중 통과 12, 차이 0, 발견 기록 0.
