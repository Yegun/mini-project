이 기록이 다루는 기간은 2026년 10월 29일 새벽 1시부터 10월 30일 오후 2시 44분까지다. 끝 지점은 `77bafd6`(PR #11 병합)이다. 참여한 사람은 Git 작성자 이름으로 Yegun, suuu29, ANHYEONGCHEOL 세 명이다. 이름만 알 수 있어서 각자 어떤 역할이었는지는 적지 않았다.

이 기록은 Git 기록(커밋 해시, 작성자, 날짜, 바뀐 파일)과 문서 본문을 근거로 썼다. 기록만으로 알 수 없는 것은 추측하지 않고 "확인 필요"라고 표시했다.

## 1. 이 브랜치에 있는 문서 소개

이 프로젝트는 "냉장고 관리 웹 앱"이다. 장 본 식품을 등록해 두면 보관 방법에 따라 먹어야 하는 기한을 계산해 주고, 이번 주 달력에 막대와 색으로 보여 주는 앱이다. 화면은 React, 서버(API)는 FastAPI, 저장소는 SQLite를 쓰기로 되어 있다. 아래는 이 브랜치에 있는 문서들이다. 대부분은 10월 26~28일에 이미 만들어져 있었고, 이 기간에 새로 생기거나 크게 바뀐 것은 뒤쪽 "작업 기록"에서 다룬다.

### 방향과 요구사항을 정하는 문서

- **PRODUCT-DIRECTION.md**: 제품 아이디어와 "바꾸지 않는 조건"을 적은 문서다. 웹 앱이고, 각자 자기 컴퓨터에서 실행하며, 배포는 이번 범위가 아니라는 점 등이 들어 있다. (처음 작성 10월 27일, `7c6042d`, Yegun)
- **PROJECT-DISCOVERY.md**: 만들고 싶은 기능 후보를 모아서 "이번에 만들 것(수락)"과 "나중으로 미룰 것(Later)"으로 나눈 문서다. 첫머리에 수락 8개, 제외 11개로 정리되어 있다. (처음 작성 10월 27일, `f5f0ae6`, Yegun)
- **PRD.md**: 제품 요구사항 문서다. 수락한 요구사항만 모아서 한 문장 설명, 사용자와 상황, 목표, 식품 정보와 상태 규칙, 범위, 사용자 스토리(US-번호), 열린 질문 순서로 정리했다. 이 브랜치 끝에서는 v0.1.1이다. (처음 작성 10월 28일, `3637e98`, Yegun)

### 앱이 어떻게 생겼는지 설계하는 문서

- **ARCHITECTURE.md**: 앱의 전체 그림이다. 화면, API, 저장소, 공통 검사가 각각 무엇을 맡는지와 데이터가 흐르는 길, 실패했을 때 흐름을 적었다. 파일 첫머리에 "작성 중"이라고 되어 있다. (처음 작성 10월 28일, `6e81b25`, Yegun)
- **USER-WORKFLOW.md**: 사용자가 앱을 쓰는 순서를 시나리오 8개로 적은 문서다. 등록하기, 직접 등록하기, 홈에서 상태 확인하기, 정보 고치기, 보관 방법 바꾸기, 다 먹음·버림 처리, 삭제, 실패했을 때 다시 시도하기가 들어 있다. 화면 모양이나 API 주소는 적지 않고 "순서"만 적는다. (처음 작성 10월 28일, `4d71033`, Yegun)
- **SCREEN-SPEC.md**: 화면 명세다. 화면 목록, 화면 사이 이동, 홈·식품 등록·식품 상세 화면의 구성, 오류와 검증, 이번 범위 밖 항목을 적었다. 새로 만든 문서다. (10월 29일, `8bb75fb`, suuu29)
- **API-SPEC.md**: 화면에서 사용자가 무언가를 눌렀을 때 서버와 화면이 어떻게 움직이는지를 적은 약속 문서다. "행동 하나에 API 하나"를 기준으로 9개 행동을 다룬다. 이 브랜치 끝에서는 초안 v0.3이다. 새로 만든 문서다. (10월 29일, `0639839`, ANHYEONGCHEOL)
- **DATA-MODEL.md**: 식품 한 건을 SQLite에 어떤 칸으로 저장하는지, 규칙표 DB는 어떻게 생겼는지를 적은 문서다. 초안 v0.1이고 새로 만든 문서다. (10월 30일, `74dc1e4`, Yegun)

### 결정과 규칙을 기록하는 문서

- **DECISIONS.md**: "이렇게 하기로 했다"를 D-번호를 붙여 하나씩 남기는 문서다. 이 브랜치 끝에서는 D-001부터 D-034까지 있다. 다른 문서들이 "(D-014)"처럼 이 번호를 근거로 가리킨다. (처음 작성 10월 28일, `ac98f2d`, Yegun)
- **AGENTS.md**: 사람과 코딩 Agent가 함께 따르는 작업 규칙이다. 작업 전에 문서를 읽을 것, 계획을 먼저 보여 주고 승인받을 것, main에서 직접 작업하지 않을 것 같은 내용이 있다. (처음 작성 10월 16일, `6e12181`, Yegun)
- **DEV-ENVIRONMENT.md**: 개발에 쓰는 컴퓨터 환경과 프로그램 버전을 `--version` 실행 결과 그대로 적은 기록이다. 확인일은 10월 28일이다. (`9e2ee34`, Yegun)

### 문서를 쓰기 위한 참고와 자료

- **PRD_refer.md**, **PROJECT-DISCOVERY_refer.md**: 수업 교재(`MZC-AICAMP-M3-VC-Day7-Workbook-v1.2`) 내용을 바탕으로, PRD와 PROJECT-DISCOVERY를 어떻게 쓰는지 정리해 둔 참고 문서다.
- **docs/references/**: 아이디어를 담은 PDF(`냉장고-앱.pdf`)와 화면 그림 7장(`UI/` 폴더: 시작, 홈, 사진 분석, 확인, 식품 상세, 기록, 설정)이 있다.

### 코드 파일

이 브랜치에는 아직 앱 코드가 거의 없다. `backend/` 에는 서버가 살아 있는지 확인하는 `/health` 주소 하나와 그 시험(`backend/app/main.py`, `backend/tests/test_health.py`)이 있고, `frontend/` 에는 Vite가 만들어 주는 기본 화면 틀이 있다. 10월 28일에 "M0 화면과 API 기본 구조"(`4cdf460`, suuu29)로 들어온 것이다. 실제 기능 코드는 이 기록의 다음 브랜치인 `feat/m1` 에서 만들어진다.
