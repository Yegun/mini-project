# FRONTEND-ERRORS — 프론트엔드 오류 정리

- 브랜치: `feat/m1-frontend`
- 범위: frontend/ 안의 오류만. 백엔드·데이터가 원인인 것은 맨 아래 "병합 시 확인"에 따로 적는다.
- 구분 방법: mock 으로 돌려도 같은 오류가 생기면 프론트 오류, mock 에서는 정상이면 병합 시 확인.

## 확인한 방법

| 확인 | 결과 |
|---|---|
| `npm run build` | 통과 |
| `npm run lint` | 통과 (경고·오류 없음) |
| 타입 검사 (`tsc`) | 통과 (build 안에서 실행됨) |
| mock `1` | 홈 · 상세 · 등록 화면 확인. 콘솔 에러 없음 |
| mock `empty` | 안내 문구 + 식품 등록 버튼, 버튼 누르면 등록 화면으로 감 |
| mock `slow` | 불러오는 중 표시, 저장·등록 중 버튼 잠김, 연타해도 요청 한 번 |
| mock `save-error` | 상세 · 등록 실패 알림 뜸, 입력값 그대로 남음 |
| mock `save-invalid` | 상세 · 등록에서 안내가 알맞은 칸 아래에 뜸, 입력값 그대로 남음 |
| mock `rules-error` | 검색 실패 알림과 다시 시도 버튼 뜸 |
| mock `detail-error` | 상세 불러오기 실패 알림과 다시 시도 버튼 뜸 |
| 화면 폭 375px, 320px | 홈 · 상세에서 겹침이나 가로 넘침 없음. 막대 자르기와 오늘 세로선 위치 정상 |

임시 확인용 브라우저 자동 조작은 프로젝트 밖에서 했고, 프로젝트 파일은 바꾸지 않았다.
실제 휴대폰, 실제 API 는 확인하지 못했다.

## 오류 목록

### 오류 1번 — 정보 고치기에서 수량·단위만 고쳐도 "기한 다시 적기" 칸이 닫히고 적은 날짜가 사라짐
- 증상: 이름을 규칙표에 없는 이름으로 바꿔 저장하면 "기한을 다시 적어 주세요" 칸이 열린다. 날짜를 고른 뒤 수량이나 단위를 고치면 칸이 닫히고 고른 날짜가 지워진다. (mock `1` 에서 두부 → 이름 "없는식품" → 날짜 선택 → 수량 변경으로 재현)
- 원인: `frontend/src/components/InfoEditForm.tsx` 의 `change()` 가 어떤 칸이 바뀌어도 기한 칸을 닫고 비운다. 코드 주석은 "이름·구매일이 바뀌면"이라고 되어 있다.
- 해결 방법: 바뀐 칸에 이름 또는 구매일이 있을 때만 기한 칸을 닫고 비운다.
- 해결 여부: 해결됨 (`InfoEditForm.tsx` 의 `change()` 에 조건 추가)

### 오류 2번 — 상세 화면에서 처리·삭제 실패 알림이 맨 위에만 떠서 아래 버튼을 누른 사람은 못 봄
- 증상: 휴대폰 크기 화면에서 상세 아래쪽 '삭제', '다 먹음', '버림'을 눌러 실패하면 오류 알림은 화면 맨 위에 생기지만 화면은 아래에 그대로 있어 아무 반응이 없는 것처럼 보인다. (mock `save-error`, 375px 에서 확인: 스크롤 496px 위치에서 알림이 화면 밖)
- 원인: `frontend/src/pages/FoodDetailPage.tsx` 가 알림만 띄우고 알림이 보이는 위치로 옮겨 주지 않는다. 확인 창이 닫히면 사용자는 아래 버튼 근처에 남는다.
- 해결 방법: 오류 알림이 새로 뜰 때 알림이 화면 안으로 오도록 스크롤한다.
- 참고: 식품 등록 화면은 페이지가 짧아 알림이 화면 안에 보여서 재현되지 않았다. 고치지 않는다.
- 해결 여부: 해결됨 (`FoodDetailPage.tsx` 에서 오류가 생기면 알림 칸으로 스크롤)

### 오류 3번 — 값이 그대로인데 글자만 다르게 고치고 저장하면 아무것도 안 바뀐 채 홈으로 이동함
- 증상: 수량 `1` 을 `01` 로 고치면 '정보 저장' 버튼이 켜지고, 누르면 바뀐 것 없이 홈으로 이동한다. (mock `1` 에서 재현. 실제 API 에서는 바뀐 칸이 없는 빈 수정 요청이 나간다)
- 원인: `frontend/src/lib/editForm.ts` 의 `isInfoChanged` 는 글자로 비교하고 `buildInfoPatch` 는 숫자로 비교해서 서로 어긋난다. 바뀐 칸이 없어도 요청이 나간다.
- 해결 방법: 검사를 통과한 뒤 바뀐 칸이 없고 기한 칸도 안 열려 있으면 요청을 보내지 않고, 입력칸을 저장된 값 모양으로 되돌려 저장 버튼이 꺼지게 한다. 잘못된 값도 눌러서 안내를 받게 하는 기존 방식은 유지한다.
- 해결 여부: 해결됨 (`InfoEditForm.tsx` 의 `submit()` 에서 바뀐 칸이 없으면 요청 없이 입력칸을 되돌림)

## 재현되지 않아 뺀 후보

| 후보 | 이유 |
|---|---|
| 화면을 옮길 때 스크롤 위치가 남아 중간에서 열림 | 옮기는 순간 "불러오는 중" 짧은 화면이 먼저 나와서 스크롤이 맨 위로 돌아감. 재현 안 됨 (홈 스크롤 119px → 상세 0px) |
| 등록 화면 실패 알림이 안 보임 | 등록 화면은 짧아서 알림이 화면 안에 보임 |

## 다음 작업 후보 (오류 아님, 이번에 고치지 않음)

- 브라우저 뒤로가기를 누르면 앱 밖으로 나간다. 화면을 상태값으로만 바꾸는 구조(App.tsx 주석에 의도라고 적힘)라서 생긴다. 고치려면 라우터 패키지 설치와 구조 변경이 필요해 이번 범위를 넘는다.

## 병합 시 확인

백엔드·데이터 쪽 원인으로 보이는 것들이다. 오류 번호를 붙이지 않았고 고치지 않는다.

1. **개발 서버 프록시**: `frontend/vite.config.ts` 가 `/api` 를 떼고(`rewrite`) 8000 번으로 넘긴다. API-SPEC 경로는 `/api/foods` 이고 백엔드에는 지금 `/health` 하나뿐이다. 백엔드 경로와 맞는지 확인한다.
2. **422 응답 모양**: 화면은 `{ errors: { 칸이름: 안내 } }` 로 가정한다. 칸 이름이 화면 칸과 다르거나 본문이 비면 등록 화면은 "등록하지 못했어요"로 대신 보여 주지만 상세 화면은 아무 안내도 뜨지 않는다.
3. **"기한 다시 적기" 응답**: `200 + { status: "need_expiry" }` 는 임시 약속이다.
4. **응답 칸 이름·값**: `expiry_level`(relaxed / caution / urgent / expired), `storage`(room / fridge / freezer), `show_on_calendar`, 상세의 `quantity · unit · source · storages`, 규칙 검색의 `rules[].default_storage · storages`, 등록 요청의 `rule_id · expiry_days`, 처리 요청 본문 `{ status }`. 값이 다르면 색·이름·막대가 어긋나고, 모르는 상태는 읽어 주는 글자에 "undefined"가 나온다.
5. **`today` 없음·형식 오류**: 홈이 오류로 하얗게 된다. `show_on_calendar` 가 빠지면 달력 막대가 모두 사라진다.
6. **정렬(D-015)과 지남 4일 이상 달력 제외(D-014)**: API 몫이라 화면은 받은 순서와 값을 그대로 쓴다.
7. **없는 식품 · 이미 처리된 식품** 요청의 오류 응답(D-008), 상세 불러오기 실패 응답.
8. **규칙표 30개 내용(D-018)**: 지금은 가짜 값(`mocks/rules.json`)이다. 불가 방법과 기본 보관 방법이 진짜 값과 다를 수 있다.
